UE-CL1-API

A closed-loop UDP interface between Cortical Labs' CL1 biocomputer and Unreal Engine — receive living-neuron spikes as gameplay events, and send electrical stimulation back as feedback.

View on GitHub → How it works

The closed loop

Neurons in, stimulation out

UE-CL1-API builds a UDP bridge between Unreal Engine and a CL1, implementing the closed loop from our NeurIPS 2025 Creative AI Track paper Assembloid Agency on top of the official CL1 spike firehose. 

   CL1 ──(neuronal spiking activity, port 12345)──▶  Unreal Engine
   CL1 ◀──(electrical stimulation, port 12346)──    Unreal Engine

Unreal only ever sees UDP, so the same plugin can drive a CL1 (via bridge.py) or an equivalent NEST / SNN / EEG stand-in that speaks the same protocol — with identical state and reward mappings across substrates.

The API surface

One Unreal subsystem, six capabilities

The plugin exposes a UCl1BridgeSubsystem — usable from both C++ and Blueprint — that handles the CL1 ↔ Unreal bridge and the full Assembloid Agency API.

Connection

StartReceiver, StopReceiver, and ConfigureControlTarget open the UDP spike listener and set the outbound control target.

Stimulation

SendStimulation, SendStimPlan, SendRewardSignal, and InterruptStim deliver biphasic pulses, coordinated multi-group bursts, and DishBrain-style reinforcement.

Recording

RecordSessionData toggles CL1-side HDF5 recording over the bridge; ExportToCSV writes the Unreal-side spike log for offline analysis.

Read-back

GetSpikeResponse, GetSpikeRateHz, and GetChannelRates expose live per-channel firing rates for gameplay and visualization.

Events

OnSpike, OnSpikeInChannel, and OnSpikeBatch fire in C++ and Blueprint, so spikes can drive gameplay directly.

Game states

DecodeState / EncodeState translate four game states ⇄ CL1 activity — a symbol-to-channel encoder and a weightless argmax decoder wired live.

Get started

Run it with no hardware

A bundled organoid simulator (LIF and Brian2 substrates) ships with the plugin, so the whole pipeline runs without a CL1. Validate the pipe with synthetic spikes, then point it at real hardware: 

# 1. Validate the whole pipe with synthetic spikes (no SDK/hardware):
python3 bridge.py --selftest --ue-host 127.0.0.1 --ue-port 12345

# 2. Biocompute organoid substrate (the real closed loop):
python3 bridge.py --organoid --control-listen-port 12346 \
        --ue-host 127.0.0.1 --ue-port 12345 --random-seed 42

# 3. Against a CL1 / simulator, bidirectional, with a safety envelope:
python3 bridge.py --ue-host 192.168.1.50 --ue-port 12345 \
        --control-listen-port 12346 --max-amp 10 --max-channel 63

A safety envelope (Assembloid §5) rejects and drops out-of-range stimulation commands — amplitude, pulse width, pulse count, frequency, and channel — rather than silently altering them. Defaults are conservative; set them to your own IRB / lab protocol.
